# 설계

## 전체 흐름

```
AI Hub 원본 ─ ingest ─┬─ Training ── 검색 지식 (QA · 상담 사례) ── LanceDB
                      └─ Validation ─ 시나리오 카드 ─┬─ dev (라운드마다 새로 뽑음, 피드백 수집)
                                                    └─ holdout 100건 (고정, 측정 전용)

라운드:  고객(AI) ⇄ 상담사(RAG) ── 심판(AI) 채점 ── dev 실패 ── triage ── 게이트 ── 다음 라운드 주입
                                                              └─ holdout 결과 ── 롤백 검사
```

## 역할과 모델

역할마다 제공자와 모델을 `config.yaml`에서 바꿉니다. 같은 인터페이스(`counsel.llm.chat`)로 호출합니다.

| 역할 | 하는 일 | 실험 설정 |
|---|---|---|
| router | 대화 맥락을 넣어 검색 질의를 다시 쓰고 주제를 분류 | GPT 계열 (Codex CLI) |
| reranker | 후보 30건에서 관련 문서를 골라 순서를 매김 | GPT 계열 (Codex CLI) |
| counselor | 근거와 적용된 수정을 보고 상담사 발화 작성 | GPT 계열 (Codex CLI) |
| customer | 시나리오 목표·성격·디지털 이해도대로 질문 | Claude Haiku |
| judge | 대화 단위 5항목 채점, 실패 태그와 턴 번호 기록 | Claude Sonnet |
| triage · gate | 수정 후보 작성과 검수 | GPT 계열 (Codex CLI) |

상담사와 심판은 다른 모델을 씁니다. 같은 모델이 자기 답을 채점할 때 생기는 선호 편향과 같은 실수를 놓치는 오류를 줄이는 설정입니다.

## 검색

- 컬렉션은 둘입니다. QA(질문·답변)와 상담 사례 요약입니다.
- BM25(Kiwi 형태소)와 BGE-M3 dense 결과를 RRF로 합칩니다.
- 컬렉션마다 후보 30건을 LLM 리랭커로 다시 고릅니다. QA 5건과 사례 3건을 상담사에게 넣습니다.
- 검색 평가 100문항에서 hybrid의 주제 일치@1은 74%, 주제 포함@5는 92%였습니다.

## 상담사

- 매 턴 전체 대화를 받는 무상태 구조입니다. 턴 단위로 저장하고 이어서 실행할 수 있습니다.
- 전화 상담 구어체 2~4문장으로 답하고, 마지막 줄에 참고한 근거 번호를 적습니다.
- 계좌 조회·처리 권한이 없다고 가정합니다. 조회 결과를 지어내지 않고 확인 경로를 안내합니다.
- 금리·수수료·한도 같은 구체 수치는 단정하지 않습니다. 근거의 수치는 다른 고객의 개별 사례이기 때문입니다.
- 다른 부서 처리가 필요하면 `[이관]`을 선언하고 통화를 끝냅니다.

## 피드백 루프

실패 사례로 상담사 지침을 고치는 것을 '사례 기반 수정'이라 부릅니다. 줄여서 '수정'이라 씁니다.

| 단계 | 내용 |
|---|---|
| triage | dev 실패와 심판 노트를 보고 수정 항목(범용·주제별)과 합성사례 후보를 만듭니다. 기존 수정 항목의 변경·퇴출도 제안합니다. |
| 게이트 | 규칙(숫자·중복·시나리오 종속)과 LLM 검수를 거칩니다. 수정은 dev 실패 대화 2건 이상의 지지가 필요합니다. |
| 적용 | 범용 수정은 최대 5개를 항상 넣습니다. 주제별 수정은 router 주제가 맞을 때만, 유사도 0.5 이상 상위 3개를 넣습니다. 합성사례는 QA 검색 지식에 추가합니다. |
| 롤백 | 다음 라운드 holdout이 직전보다 나빠지면 그 라운드 채택분을 롤백합니다. |
| 사람 거부 | `feedback veto`로 언제든 끕니다. `restore`로 되돌립니다. |

롤백 기준은 5개입니다. 하나라도 걸리면 롤백합니다.

| 기준 | 값 |
|---|---|
| 종합점수 하락 | 0.10 초과 |
| 합격률 하락 | 5%p 이상 |
| 문제해결 점수 하락 | 0.2 이상 |
| 부적절이관 태그 증가 | 대화당 0.15 이상 |
| 이관으로 끝난 통화 비율 증가 | 20%p 이상 |

라운드는 시작할 때 적용 수정 목록을 `manifest.json`에 고정합니다. 중간에 멈췄다가 다시 실행해도 같은 조건으로 이어집니다.

## 앱

| 화면 | 내용 |
|---|---|
| 상담 | 고객 역할로 질문합니다. 답변마다 근거·진단 패널(검색 질의, 단계별 시간, 적용 수정, 근거 자료와 인용 여부)이 붙습니다. |
| 지표 · 라운드 비교 | holdout 합격률·종합점수·5항목·통화 결과, 라운드 간 유의성, 주제별 성적, 실패 태그 |
| 지표 · 수정 · 합성사례 | 항목별 상태와 이력 |
| 지표 · 내 상담 기록 | 앱 상담의 응답 시간, 근거 인용, 수정 적용, 이관 |

- 서버는 127.0.0.1에만 엽니다.
- 상담 엔진(임베딩 모델과 인덱스)은 프로세스당 한 번 불러옵니다. 수정 구성을 바꿀 때는 임베더를 공유하는 검색기 복사본(`Retriever.fork`)을 씁니다.
- 앱의 LLM 호출은 사용량 한도에 걸려도 기다리지 않고 바로 오류를 냅니다(`llm.set_interactive`).
- 고객·모델 문장은 마크다운으로 해석하지 않습니다. '3~5일'의 `~`가 취소선으로 바뀌지 않습니다.
